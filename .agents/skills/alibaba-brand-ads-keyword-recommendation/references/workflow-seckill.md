# 秒杀推词工作流程

本文档覆盖秒杀推词场景的完整执行流程。进入本流程前，SKILL.md 的 Step 1（产品线确认 + 场景识别 + 画像生成）必须已完成。

必须严格按照【关键词搜索】->【关键词筛选】->【推词报告生成】的顺序执行。
---

> `workctl icbu ads search-list` 未返回候选词集合前，禁止进入筛选。候选集为空时直接进入报告生成（告知无结果）。

## Step 2：关键词搜索

**目标：** 基于客户画像和推词方向，确定 `search-list` 的调用策略，获取广泛且相关的候选关键词集合。

### 2.1 搜索策略确定

基于用户表达结合客户画像，确定 `workctl icbu ads search-list` 的调用参数。客户表达可能较口语化（如"帮我推荐一些词"、"有什么适合我的词"），需灵活理解。以下各参数独立决策，可组合使用。

**购买赠送类型（purchaseType）：**
- 默认传购买词 → purchaseType=1
- 用户明确要求"购买词" → purchaseType=1
- 用户明确要求"赠送词"（顶展）或"可赠送可购买词"（问鼎）→ purchaseType=2

**售卖状态（sellStatus）：**
- 默认 sellStatus=0（可预定）
- 用户要求查看"可打标竞价的词" → sellStatus=1
- 用户要求查看所有状态 → 不传该参数

**中心词（keywordList）：**
- 用户指定了中心词 → 直接使用
- 未指定时 → 基于用户推词意图结合客户画像生成

**商品 ID（goodsIdList）：**
- 默认不传
- 用户指定了具体商品或商品 ID → 传入对应 ID 列表

**行业 ID（cateIdList）：**
- 默认不传
- 当用户表达按特定行业推词时，首先调用 `workctl icbu ads list-customer-goods-cate-summary --format json` 获取客户店铺的行业信息，选择语义最匹配的三级类目 ID 作为参数。若返回结果中没有匹配的行业 ID，则不传该参数，但需显式告知用户。

**排序规则（requestOrderProperty.orderField + requestOrderProperty.orderType）：**
- 默认 yearImps desc（按曝光指数降序）
- 用户关注转化 → busiRate desc
- 用户关注点击 → yearClk desc
- 用户关注商品关联 → relateProductNum desc

**分页参数（requestPage）：**
- pageIndex：分页索引，从1开始
- pageSize：每页大小，固定传100作为每页大小


### 2.2 中心词规范

- 中心词仅支持**英文**。
- 避免使用过于宽泛、与核心商品不相关的中心词。例如：您的核心商品是男士卫衣，应使用 `men hoodie`、`men sweatshirt` 等精准词，而非 `clothes`、`clothing` 等过于宽泛的词。

### 2.3 执行搜索

调用 `workctl icbu ads search-list` 获取候选词：
- **默认分页大小（pageSize）：** 100
- **排序及筛选参数：** 按 2.1 搜索策略确定的结果传入

**调用示例**：
```bash
workctl icbu ads search-list \
  --productId 110102001 \
  --keywordList @keywordList.json \
  --requestPage '{"pageIndex":1,"pageSize":100}' \
  --requestOrderProperty '{"orderField":"yearImps","orderType":"desc"}' \
  --sellStatus 0 \
  --purchaseType 1 \
  --format json
```

## Step 3：关键词筛选

**目标：** 从候选词集合中，依据严格的策略，精选出最具价值、最符合您业务目标的最终推荐列表。

### 策略一：相关性准入（Relevance Admission）

**1.1 匹配用户即时意图（最高优先级）**

**1.2 匹配客户业务画像**
在不违背用户意图的前提下，筛选与画像高度相关的词：
- **正面匹配：** 关键词应与您的主营行业、核心商品、技术优势、目标市场等强相关。
- **反面排除：** 必须排除画像中明确标注为"应规避"或"非核心"的领域。

### 策略二：候选词价值排序（Value Ranking）

对通过相关性准入的关键词，按以下优先级顺序进行打分和排序，筛选出 Top N（默认 25-30 个）：

| 优先级 | 维度 | 说明 | 内部顺序 |
|--------|------|------|----------|
| 1 | 店铺商品匹配 | 关键词能体现您店铺商品的核心特点与优势 | - |
| 2 | 历史效果匹配 | 您店铺历史表现优异的词 | 高询盘词 > 高P4P消耗词 > 高引流词 |
| 3 | 历史偏好匹配 | 符合您历史选词模式（如："规格+品类"） | - |
| 4 | 近期行为匹配 | 您近期有高意向行为的词 | 预定 > 竞拍 > 打标 > 收藏 |
| 5 | 关键词效果数据 | 依据客观数据指标排序 | 见下方详细说明 |

**关键词效果数据排序规则（优先级 5）：**
1. **流量优先：** 年PV指数排名（从高到低）
2. **转化效率优先：** PV指数相近时，按全站搜索点击率（从高到低）
3. **性价比优先：** 点击率也相近时，按（原价 / 预估点击上限）的比值（从低到高）

### 策略三：补量策略（Augmentation Strategy）

如果经过上述筛选后，关键词数量未达到要求（用户指定数量或默认数量），必须按以下顺序启动补量，直至满足数量或策略用尽：

1. **增加分页：** 在现有搜索条件下，请求后续分页（Page 2, 3...）的数据，重新执行筛选流程。
2. **调用无中心词搜索：** 若增加分页后仍不足，调用 `search-list` 时不传入中心词（或传空数组），获取算法基于整个店铺推荐的更广泛的关键词集，再次执行筛选。
3. **如实告知：** 如果执行完所有补量策略后数量仍严重不足，停止补量。在最终报告中明确告知："符合高质量标准的相关关键词较少，因此本次仅推荐以下 X 个关键词"，并提示可以提供更具体的中心词/商品/目标市场以便进一步扩展。

### 产出

一份数量达标、经过多维度验证的最终关键词推荐列表。

## Step 3.5：推荐结果自检

> 自检清单全部检查项未通过前，禁止生成最终报告。

在生成报告前，必须对推荐列表执行以下检查，**全部通过后方可进入 Step 4**：

| 检查项 | 规则 | 失败处理 |
|-------|------|---------|
| 数据溯源 | 每个推荐词必须可追溯至 `search-list` 返回结果 | 移除无法溯源的词 |
| 数量达标 | >= 20 个，或已穷尽全部补量策略 | 未穷尽则继续补量 |
| 规避词过滤 | 列表中不包含画像规避清单中的词 | 移除并替补 |
| 去重检查 | 无重复关键词和渠道均相同 | 去重 |
| 字段完整性 | 每个词的 12 列字段均有值 | 缺失字段标注"-" |
| 排序一致性 | 优先级排序与 5 级价值排序逻辑一致 | 重新排序 |

---

## Step 4：推词报告生成

**目标：** 将最终推荐结果以清晰、专业、有说服力的形式呈现给客户。报告全程使用第二人称（"您"），语言通俗易懂，突出业务价值。

### a. 客户画像解读

以确认式口吻向客户展示系统对其业务的理解，让客户验证系统理解是否准确，同时阐明这些信息如何指导了本次推词。

### b. 推荐策略

用通俗语言解释本次推词的核心逻辑，例如：

> "本次为您推荐的关键词，是综合分析了您店铺的高询盘词、商品特点和流量潜力后精选出的。我们优先为您挑选了与您核心商品高度匹配、买家搜索量大的关键词。"

避免使用内部术语（如"5 级价值排序"、"相关性准入"等）。

### c. 推荐结果

以 Markdown 表格形式呈现最终的关键词列表，表格必须完整包含以下所有列（数据来自 `search-list` 返回结果，禁止虚构和伪造数据，当数据不存在时使用"-"表示）：

| 字段名 | 说明 |
|--------|------|
| 优先级 | 推荐优先级排序 |
| 关键词 | 英文关键词 |
| 端型 | 终端类型（PC/APP） |
| 推荐理由 | **必须为每个词生成一句精炼的、偏业务价值的推荐语**。要求差异化，避免重复|
| 原价 | 关键词原价 |
| 预估点击量上限 | 预估点击量上限 |
| 预估点击量下限 | 预估点击量下限 |
| 关键词搜索首位点击率 | 搜索首位点击率 |
| 年PV指数排名 | 年PV指数排名 |
| 全站商机转化率 | 全站商机转化率 |
| 关键词售卖状态 | 关键词工具返回的售卖状态 |
| 全站搜索点击率 | 全站搜索点击率 |

### d. 温馨提示

每份推词报告的最后，必须附加以下提示：

```markdown
---
> **温馨提示**：
> 1. 如果本次推荐结果不完全符合您的预期，您可以通过以下方式告诉我，我会为您重新优化：
>    - 补充您想要的关键词方向（如：从"衣服"改为"男士卫衣"）
>    - 指定筛选条件（如：只看流量高的词、限定预算范围）
>    - 提供您最想推广的商品ID
>    - 直接告诉我您希望调整的方向
> 2. 如果您对推荐结果满意，可以直接告诉我您想预定的关键词（如"帮我预定优先级前5个"、"预定 dress 和 summer dress"），我可以直接为您完成预定，无需前往 MA 后台操作。
> 3. 您也可以通过以下路径手动预定：**MA后台 → 营销中心 → 品牌关键词**。关键词的实际价格与是否可预定，以预定系统为准。
>
> 我会根据您的反馈优化推荐策略。
```

## 注意事项：
| 默认数量 | 若用户未指定，秒杀场景默认推荐 **25-30** 个关键词 |
| 默认状态 | 秒杀场景默认推荐 **可预定** 状态的 **购买词** |
| 中心词语言 | 调用工具时使用的中心词列表仅支持 **英文** |

## 禁止行为

- **禁止**跳过自检步骤直接生成最终报告
- **禁止**在最终推荐结果中只展示部分推荐结果，必需给用户完整展示所有的推荐资源
