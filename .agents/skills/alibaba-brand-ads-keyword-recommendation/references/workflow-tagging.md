# 打标推词工作流程

本文档覆盖打标推词场景的完整执行流程。进入本流程前，SKILL.md 的 Step 1（产品线确认 + 场景识别 + 画像生成）必须已完成。

**场景说明：** 本场景的目标是帮助您在每月 25 号公示日前，盘点同行即将释放、且可打标跟进的关键词资源。工具返回的所有词均会完整展示，并按与您业务的匹配程度进行优先级排序，辅助您做出决策。

必须严格按照【获取打标候选词集】-> 【关键词优先级排序】->【推词报告生成】的顺序执行。
---

> `workctl icbu ads search-next-month-auction-resource` 未返回候选词集合前，禁止进入筛选。候选集为空时直接进入报告生成（告知无结果）。

## Step 2：获取打标候选词集

**目标：** 调用 `search-next-month-auction-resource`，获取次月同行释放的推荐打标词集合。

### 2.1 直接获取词集

调用 `workctl icbu ads search-next-month-auction-resource --productId <productId> --sellNode nextFirstAuctionWord --format json`，获取"次月同行释放的推荐打标词集合"。该工具返回的词集为本场景的**唯一候选集**，且**全量展示给客户**，不做删减。


### 2.2 用户表达规范

向客户展现为自然的盘点动作：
- "正在为您盘点下月同行释放、当前可提前打标跟进的关键词资源"
- **禁止**暴露工具名称或调用细节。

### 产出

返回的完整次月同行释放词候选集合（全量保留，不做裁剪）。

---

## Step 3：关键词优先级排序
**目标：** 对工具返回的全量候选词进行优先级排序。**本步骤不移除任何关键词**，所有工具返回的词均需展示。

### 三层排序机制

排序采用分层优先级，上层优先级严格高于下层：

```
第一层（最高优先级）：用户意图匹配
第二层（次高优先级）：客户画像匹配
第三层（基础优先级）：五级价值排序
```


当用户没有明显意图时，跳过第一层，直接从第二层开始。

**第一层：用户意图匹配**

将全量词分为"符合用户意图"和"不符合用户意图"两组，符合的整体排在不符合的前面。

- **有明显意图：** 用户表达中包含了具体的关键词方向、品类、商品、行业等限定条件（如"帮我看看 hair dryer 相关的打标词"）
- **无明显意图：** 用户仅表达了打标推词诉求，未做进一步限定（如"帮我盘点下月可打标的词"）→ **跳过本层**，直接进入第二层

**第二层：客户画像匹配**

在第一层的每个分组内部（或跳过第一层时在全量词集上），将词分为"符合客户画像"和"不符合客户画像"两组，符合的排在不符合的前面。

- **符合画像：** 与客户主营行业、核心商品、橱窗商品方向一致，或与历史高效果词（高询盘/高P4P/高引流）同品类同词根，或与历史选词偏好模式一致
- **不符合画像：** 与主营方向无明显关联，或属于画像规避清单中的词（定位不符、竞品品牌词、品类跨度过大、竞争超出能力）。其中规避词在组内进一步排至末尾

**第三层：五级价值排序**

在每个分组内部，按以下优先级排序：

| 优先级 | 维度 | 说明 | 内部顺序 |
|--------|------|------|----------|
| 1 | 店铺商品匹配 | 关键词能体现您店铺商品的核心特点与优势 | - |
| 2 | 历史效果匹配 | 您店铺历史表现优异的词 | 高询盘词 > 高P4P消耗词 > 高引流词 |
| 3 | 历史偏好匹配 | 符合您历史选词模式 | - |
| 4 | 近期行为匹配 | 您近期有高意向行为的词 | 预定 > 竞拍 > 打标 > 收藏 |
| 5 | 关键词效果数据 | 依据客观数据指标排序 | PV排名 → 点击率 → 性价比 |


处理原则：
- 工具返回有数据 → 全量排序后输出
- 工具返回为空 → 明确告知："当前暂无次月同行释放的可打标词资源。建议关注后续月份的释放资源。"

### 产出

基于全量词集、经三层排序后的完整推荐列表。

---

## Step 3.5：推荐结果自检

> 自检清单全部检查项未通过前，禁止生成最终报告。

在生成报告前，必须对推荐列表执行以下检查，**全部通过后方可进入 Step 4**：

| 检查项 | 规则 | 失败处理 |
|-------|------|---------|
| 数据溯源 | 每个推荐词必须可追溯至 `search-next-month-auction-resource` 返回结果 | 移除无法溯源的词（仅限非工具返回的幻觉词） |
| 全量完整性 | 工具返回的所有词均已包含在列表中，无遗漏 | 补回遗漏的词 |
| 去重检查 | 无关键词和渠道重复关键词 | 去重 |
| 字段完整性 | 每个词的必要字段均有值 | 缺失字段标注"-" |


---

## Step 4：推词报告生成

**目标：** 将全量排序结果以清晰、专业、有说服力的形式呈现给客户。报告全程使用第二人称（"您"），语言通俗易懂，突出业务价值。

### a. 客户画像解读

与秒杀场景一致，以确认式口吻向客户展示系统对其业务的理解。

### b. 推荐策略

需说明本次推荐的特殊来源和全量展示逻辑，例如：

> "本次为您盘点的关键词，来源于下月同行释放、当前可提前打标跟进的关键词资源。我们已将这批资源按照与您业务的匹配程度进行了优先级排序，标注为"重点推荐"的关键词与您的业务匹配度最高，建议优先关注。所有可打标的词均已列出，方便您全面了解和自主选择。"

### c. 推荐结果

按分组依次呈现，每个分组使用独立的 Markdown 表格，分组标题标注分组标签和说明。

**表格字段：**

| 字段名 | 说明 |
|--------|------|
| 优先级 | 组内排序序号 |
| 关键词 | 英文关键词 |
| 端型 | 终端类型（PC/APP） |
| 推荐理由 | 依据分组和排序维度生成差异化推荐语（见下方示例） |
| 原价 | 关键词原价 |
| 预估点击量上限 | 预估点击量上限 |
| 预估点击量下限 | 预估点击量下限 |
| 关键词搜索首位点击率 | 搜索首位点击率 |
| 年PV指数排名 | 年PV指数排名 |
| 全站商机转化率 | 全站商机转化率 |
| 关键词售卖状态 | 基于工具真实返回数据如实展示，不得编造或强行转换 |
| 全站搜索点击率 | 全站搜索点击率 |

**推荐理由差异化示例：**
- **重点推荐组：** "与您核心商品高度匹配的同行释放词，建议尽早打标跟进"
- **意图相关组：** "符合您本次关注的方向，可重点评估"
- **业务相关组：** "与您的业务匹配，虽不在本次指定方向内，但可作为拓展选择"
- **仅供参考组：** "与您当前主营方向关联度较低，仅供了解"

## 禁止行为

- **禁止**执行补量策略（打标场景不支持翻页、扩词、无中心词搜索等补量操作）
- **禁止**跳过自检步骤直接生成最终报告
- **禁止**在最终推荐结果中只展示部分推荐结果，必需给用户完整展示所有的推荐资源
