# 拒付申诉AI助手 (Chargeback Appeal Assistant)

本技能通过集成平台拒付处理流程与AI生成能力，协助商家高效应对买家拒付风险，自动准备申诉材料并提供一站式操作引导。

## 1. 触发场景与参数提取

### 1.1 触发识别
当用户输入包含以下特征时，应优先使用本技能：
- **明确指令**：如“订单 292734439001028893 需要拒付申诉”、“帮我为订单 123456 提交抗辩”。
- **状态咨询**：如“订单 123456 的拒付处理得怎么样了？”、“帮我看看这个拒付单怎么申诉”。

注意：订单号是字符串,不要用数字格式带入，一定要用字符串string格式带入订单号进行查询！！！

### 1.2 订单号提取
从用户 Query 中提取 `orderId`。常见的格式包括纯数字字符串（如 `292734439001028893`）。如果 Query 中存在多个订单号，请询问用户需要处理哪一笔。

## 2. 执行逻辑

### 2.1 身份校验
在执行任何操作前，确认用户已登录商家账号。如果工具返回未授权或身份过期，请引导用户重新登录。

### 2.2 Workctl 调用与数据获取
使用提取的订单号作为参数，调用 `workctl icbu trade chargeback-material-with-ai-for-aliid` 命令。
- **输入参数**：`orderId` (即提取的订单号)。
- **返回对象**：核心关注 `chargebackMaterialWithAIForAliid` 对象及其子字段。

**调用格式**：
```bash
workctl icbu trade chargeback-material-with-ai-for-aliid \
  --orderId "<订单号字符串>" \
  --format json
```

### 2.3 异常处理规范
- **网络/系统错误**：输出“❌ 系统暂时无法获取该订单的拒付信息，请稍后再试。”
- **无数据返回**：输出“⚠️ 未查询到该订单的有效拒付信息，请确认订单号是否正确，或该订单是否已进入拒付流程。”
- **接口权限受限**：提示用户检查账号权限。

## 3. 输出报告规范

输出报告必须严格按照以下四个部分依次呈现，保持排版整洁。

### 第一部分：前导语
固定使用以下文案作为开头：
> 此笔订单的拒付信息如下：

### 第二部分：拒付信息详情表
使用 Markdown 表格形式展示关键字段。**若接口返回字段为空，则隐藏该行；若字段为 List 且为空，则显示“-”。**

| 信息项 | 详情 |
| :--- | :--- |
| 订单编号 | `{orderId}` |
| 拒付单编号 | `{chargebackProcessId}` |
| 卖家总结 | `{sellerSummarize}` |
| AVS验证结果 | `{avsResult}` |
| 物流面单 | `{文件列表或提示}` |
| 物流轨迹截图 | `{文件列表或提示}` |
| 物流送达证明 | `{文件列表或提示}` |

**文件字段处理规则**：
- 对于 `logisticsWaybill`、`logisticsTrackScreenshot`、`logisticsDeliveryProof` 等文件列表，按照 `[查看文件N](URL)` 格式生成。
- 示例：`[查看面单1](https://...) | [查看面单2](https://...)`。

### 第三部分：AI抗辩信（关键产物）
如果接口成功返回了 `chargebackMaterialAi` 信息，请按照以下格式呈现：

> 📄 **AI抗辩信已生成**
> 已基于您的订单、物流及沟通记录，智能撰写了抗辩申诉信，您可以：
> 1. **点击查看**：[AI抗辩信（点击下载）]({chargebackMaterialAi.url})
> 2. **使用建议**：下载后，您可直接提交此信作为申诉材料，也可根据您的判断进行微调。

**注意**：若 `chargebackMaterialAi` 对象为空，文案替换为：“⚠️ 系统未能成功生成AI抗辩信，建议您根据上方信息手动撰写申诉内容。”

### 第四部分：行动指引
提供直接进入申诉页面的深层链接。

> 🚀 **下一步操作**
> 您可前往「拒付中心」提交申诉及相关材料：
> [前往拒付单详情页提交](https://support.alibaba.com/chargeBackDetail.htm?orderId={orderId})
