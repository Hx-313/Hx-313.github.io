## 空数据区块处理 & 动态编号规则（强制）

> **`{{N}}` 占位符说明**：模板中所有 `{{N}}` 均为**动态序号标识符**，不是固定值。输出时必须根据实际展示的区块顺序，从一（1）开始依次递增计算得出真实序号，再替换 `{{N}}`。子章节的 `{{N}}.1`、`{{N}}.2` 中的 N 同理，取其父区块的实际序号。

当某个区块因接口返回空数据而无法展示时，**必须跳过该区块，并对剩余区块重新编号**，保持序号连续。

**数据有效性前置检测：**
在生成简报前，先检查步骤 1 的核心工具 `store_diagnose_brief` 是否返回成功。若该接口失败或返回空，**立即提示**"正在连接数据接口，请稍后再试"，不输出空壳简报。

**处理规则：**
1. 逐区块检查数据可用性，无数据的区块直接跳过（不输出标题、不输出"暂无数据"占位）。**例外：流量结构分析、商品健康度分析、服务能力评估为首屏强制区块，只要接口成功就必须展示，数值低或为 0 不算"无数据"，不得跳过**
2. **严禁保留空表格** — 若某模块返回的数据数组长度为 0，必须移除该子标题，或替换为一句话提示（如"本周暂无异常提醒"）
3. 生成正文前，先在内部构造"实际输出区块清单"，只包含本次会展示的区块标题；不要输出这份清单
4. 剩余区块按"实际输出区块清单"的出现顺序重新编排中文数字序号（一、二、三……），确保用户看到的序号连续无断档
5. 子章节编号（如 N.1、N.2）跟随父区块序号同步调整
6. **子母序号联动（硬性校验）** — 子章节编号的第一个数字 N **必须**与当前父章节的实际大写序号保持绝对一致。例如：若某区块因跳过后实际排序为第三个展示区块，则其下属子章节必须起始于 `3.1`、`3.2`，严禁出现父章节为"三"但子章节为 `1.1` 或 `4.1` 的错位情况
7. "行动建议"和"猜你想问"始终保留，分别作为倒数第二和最后一个区块；但它们的序号仍由实际位置决定，严禁固定为"八"和"九"

**模块级兜底策略：**

| 区块 | 空数据判定条件 | 兜底处理 |
|:---|:---|:---|
| 一、核心经营概览 | `data_advisor_shop_summary` 失败**且** `weekDiagnose` 为空（两者都无数据） | 跳过该区块，提示"本期暂无经营诊断数据" |
| 1.1 流量转化漏斗 | 搜索曝光值 = 0 | **不画漏斗**，替换为"暂无足够数据生成漏斗" |
| 1.2 核心指标竞争力 | `advisor.rival` 和 `weekDiagnose.valueVsAvg` 均缺失 | 跳过该子章节 |
| 二、实时业务看板 | `orders` 和 `im` 均失败 | 跳过该区块 |
| 三、流量结构分析 | 周报接口失败（`invokeStatus` 非 completed/success） | 跳过该区块。**周报成功但渠道/地域数组为空时，分别以"暂无渠道分布数据"/"暂无买家地域数据"一句话兜底，不跳过整个区块** |
| 四、商品健康度分析 | `data_advisor_shop_summary` 接口失败（非数据为空） | 跳过该区块。**爆品=0、优品极少等低值情况必须正常展示，不得跳过。** 只要接口成功就渲染商品分层表格 |
| 五、服务能力评估 | 周报 `STORE_COMMUNICATION_CONVERSION_OVERVIEW` **和** advisor 服务指标均无数据（两者都失败） | 跳过该区块。**周报该模块为空但 advisor 有回复率/回复时长时，用 advisor 指标兜底渲染，不得跳过。** 仅周报独有的字段（已读未回率、服务满意度）标注"暂无数据" |
| 六、广告投放概览 | `icbu-ads-report-load-datasource` 返回失败或 `total_rows` 为 0 | 跳过该区块 |

**优雅降级：** 当某个 workctl 命令在当前环境不可用（如接口未部署或超时），跳过依赖该命令的区块，不影响其余区块正常输出；不要把失败命令降级成 0 值空数据。
