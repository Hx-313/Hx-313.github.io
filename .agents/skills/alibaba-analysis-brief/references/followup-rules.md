# 追问后处理规范

> 每次回答用户追问后，依次执行以下操作。

## 1. 追问回复规范

**追问回复必须遵循以下规则：**
1. **禁止出现任何 Skill 英文名称**（如 `p4p_optimization_skill`），所有建议必须使用中文 Skill 名称（如「智投优化」）
2. **简短为主，客观数据优先** — 回复以数据表格和关键数字为核心，减少冗长文字描述，让数据说话
3. **不要出现"后续引导"区块** — 禁止在追问回复中输出"需要根据分析结果更新 Skill 配置"等系统性引导文字
4. 追问回复的结尾仅保留"定时任务引导"（见下方第 2 步）

## 2. 引导定时任务（仅在追问后 + 无激活任务时）

**此引导仅在用户进行追问并回答完成后才触发，首次生成经营简报时禁止展示。若步骤 0.7 已在首次回复中创建了定时任务，追问后也不再重复引导。**

追问回答完成后，询问用户是否需要开启定时任务。

先检查是否已有激活的定时任务：

```bash
cat "$WORKSPACE_DIR/.accio/cron/jobs.json"
```

> 💡 `$WORKSPACE_DIR` 为 Accio 平台标准环境变量，指向当前工作空间根目录。

- 查看返回的 JSON 中是否已存在包含「店铺经营分析」相关的定时任务条目
- 如果已存在：**跳过引导**，不再询问用户
- 如果不存在或文件不存在：在追问回复末尾询问：

> "需要开启「店铺经营分析」定时任务吗？（如每周一自动生成经营简报）"

**引导规则：**
- **使用中文名「店铺经营分析」**，不要使用英文 skill 名称
- **不要提及具体指标模块**
- 如果用户确认：
  1. 收集频率偏好（每日/每周/每月）
  2. 将需求整理为结构化描述，交由对话系统自动创建定时任务；没有拿到系统返回的 jobId/下次执行时间前，禁止说"已创建定时任务"
- 如果用户拒绝或忽略：跳过，继续等待下一个追问

**注意：** 定时任务的创建和管理由 phoenix-pc 平台的对话系统自动处理，本 Skill 只负责引导提示，不需要维护定时任务配置。
