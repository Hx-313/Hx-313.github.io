## 1. 工具与意图路由

### 1.1 工具

| 工具名 | 用途 | 调用形态 |
|---|---|---|
| `farseer_topic_search` | 推荐 / 搜索 / 筛选合一的定招主题查询 | `{ scene, topicSceneQuery }`，`topicSceneQuery` 始终是完整的 16 字段对象(§3) |
| `query_user_valid_category` | 查询商家权限类目，返回扁平 Map | `{ language }`，返回 `Map<cateId, {name, parentId, level}>`（§1.5.3） |

⚠️ **调用防错警告**：
*   `query_user_valid_category` 和 `farseer_topic_search` 是**独立注册**的工具名。
*   **严禁添加 `farseer.` 或任何其他前缀**。错误的臆造命名会导致调用失败。

**language**（两个查询工具格式不同，不可混用）:

| 用户语言 | `query_user_valid_category` | `farseer_topic_search` |
| ---- | --------------------------- | ---------------------- |
| 中文   | `"zh"`                      | `"zh_CN"`              |
| 英文   | `"en"`                      | `"en_US"`              |

`query_user_valid_category` 结果在同一会话中**可直接复用**，无需重复调用。

### 1.2 意图识别决策树

```
用户输入
  │
  ├─ 含 "已发品" 语境 → 推荐 + hasDirectProduct=true（§4.1）
  │
  ├─ 判定为【发品意图】→ 转 topic-listing.md 发品流程
  │     ├─ 本会话有前置查询 → 直接调用发草稿流程（默认）
  │     ├─ 本会话无前置查询 + 有 topicId → 先查出主题信息再确认发品
  │     └─ 本会话无前置查询 + 无 topicId → 告知需先查询 / 引导进入查询
  │
  ├─ 含热卖关键词（§5.3 热卖路由）
  │     ├─ 不涉及类目词 → 推荐 + 热卖筛选，**不触发类目鉴权**
  │     └─ 同时涉及类目词 → 类目鉴权（§1.5）+ 热卖筛选叠加
  │
  ├─ 判定为【类目筛选】（§1.3.2）→ 类目鉴权（§1.5）
  │     ├─ 通过 + 含关键词 → 类目+关键词组合（§4.3）
  │     ├─ 通过 + 无关键词 → categoryId 筛选（§4.3）
  │     └─ 不通过 → 告知无权限 + 展示可用类目
  │
  ├─ 判定为【主题名称搜索】（§1.3.3）→ 搜索（§4.2），orderByName = "lst_tgd_prod_payed_byr_growth"
  │
  ├─ 判定为【模糊型】（§1.3.4）→ 先类目匹配；不到则退化为主题名称搜索（orderByName 同上）
  │
  ├─ 含纯数字主题 ID → topicIds 精查（§4.2）
  │
  ├─ 翻页语境 → 沿用上次条件，currentPage+1（§8）
  │
  ├─ 含 tab / 国家 / 标签筛选词 → 叠加筛选（§4.3）
  │
  └─ 其他 → 推荐（§4.1）
```

优先级 = 已发品 > **发品意图** > **热卖筛选** > 类目筛选 > 主题名称搜索 > 模糊型 > 搜索 > 翻页 > 筛选 > 推荐。

⛔ **停止条件（硬要求）**：每个分支搜索结束后**立即停止**，禁止追加工具调用。明确搜索返空 → 报空停止，禁止缩短关键词/退化类目。**例外情况**：精确搜索（ID 或主题全称 §1.3.3）在交易品搜索为空时，**允许自动切换商机品业务线重搜一次**。**模糊型两步均空（类目匹配无果 + 主题名称搜索无果）→ 立即报空停止，禁止任何额外查询**（详见 §1.3.4）。网络错误自动重试一次。

### 1.3 主题意图识别与路由规则

#### 1.3.1 路由总览

| 类型 | 触发条件 | 示例 |
|---|---|---|
| **类目筛选** | ① 含"类目/行业/品类"修饰词；② 含 `>>` 或 `->` 路径；③ 类目字典完整匹配 | "隔音材料**类目**下的主题"、"家居园艺 >> 儿童收纳" |
| **主题名称搜索** | ① 含"主题名称"修饰词；② 引号/中括号包裹；③ 定招主题标题特征（§1.3.3） | "[密封式储物盒]主题"、"双面压敏聚酯基材胶粘纸" |
| **模糊型（默认）** | 以上均不满足，仅限**短泛产品词** | "挖掘机相关商品"、"早餐机链接" |

路由总览中共 3 类（类目筛选 / 主题名称搜索 / 模糊型）。发品意图路由已下沉到 [`topic-listing.md`](topic-listing.md) §2。

**核心原则**：类目名是短泛行业概括（2~6 字），主题标题是带多重修饰的具体商品定义（≥ 8 字）。长描述 → 主题名称搜索，短泛 → 模糊型。

#### 1.3.2 类目筛选路由

- Query 含"类目、行业、品类"等关键词
- Query 含结构化路径 `>>` 或 `->`

#### 1.3.3 主题名称搜索路由

以下情况直接走 `farseer_topic_search`（`orderByName = "lst_tgd_prod_payed_byr_growth"`）：

- ① Query 含"主题名称"修饰词
- ② 内容被引号 `""` 或中括号 `[]` 包裹
- ③ **呈现定招主题标题特征**：

| 特征 | 示例 |
|---|---|
| **多重修饰词堆叠**（≥3 个修饰成分） | "双面压敏聚酯基材胶粘纸" |
| **含具体规格/数值** | "含牛磺酸维生素强化150ml瓶装" |
| **含加工状态/形态描述**（颗粒状、固态、干燥型等） | "颗粒状干燥型单一品种辣椒粉" |
| **字数 ≥ 8 且非通用行业词** | "无咖啡因成人用袋装瘦身茶包" |
| **用户说"查主题/找主题/搜主题"** | "查主题：无咖啡因成人用袋装瘦身茶包" |

> ❌ "无咖啡因成人用袋装瘦身茶包" → 提取"瘦身茶包" → 匹配到"减肥茶"类目
> ✅ 识别为主题标题 → 直接走主题名称搜索

#### 1.3.4 模糊型 Query 处理

不满足 §1.3.2 和 §1.3.3 时走此流程：

1. **先类目匹配**：调 `query_user_valid_category`，按精确 → 相似匹配（§1.5.2）查找
2. **匹配到** → 用 cateId 走筛选（§4.3），输出说明匹配到的类目（§9.5）
3. **未匹配** → 退化为主题名称搜索，`title` 填用户输入（§4.2）

**⛔ 两步均空即终止（铁律）**：类目匹配无结果 → 退化主题名称搜索仍无结果 → **立即以空结果结束**，按 §9.5 空结果模板输出。禁止自行缩短关键词重搜、换类目、切业务线、去掉筛选条件、或任何自由发挥的额外查询。模糊型最多只允许**两次工具调用**（类目查询 + 主题搜索），不允许第三次。

**不走类目的例外**：纯英文产品型号（如 "IP67 M23 connector"）或明显非行业/品类词的商品描述，直接走关键词搜索，不尝试类目匹配。

### 1.4 类目匹配优先级

| 规则 | 示例 |
|---|---|
| **父类目 > 子类目**（level 小的优先） | "灯具"命中 level=1 和 level=3 → 用 level=1 |
| **全词匹配 > 部分匹配** | "家居园艺"完全匹配 > "家居"部分匹配 |
| **路径取最深节点** | "家居园艺>>蜡烛与香薰" → 用"蜡烛与香薰" |

### 1.5 类目权限校验（类目鉴权）

#### 1.5.1 校验步骤

1. 调 `query_user_valid_category` 获取类目 Map（会话内可复用缓存）
2. 匹配用户指定类目：数字 ID → O(1) 查找；中文名 → 精确匹配 → 相似匹配（§1.5.2）→ 多个命中按 §1.4 选取
3. 匹配到且在权限内 → 继续调 `farseer_topic_search`；不在权限内 → 告知 + 展示可用类目
4. 调用失败 → 重试一次；仍失败则报错终止

**铁律**：所有类目路径都**必须经过鉴权**，不可跳过。

**豁免场景**：纯热卖筛选路径（仅含热卖关键词如"市场热卖""热卖""站内热卖"等，不涉及类目词/类目路径）无需类目鉴权，直接走推荐+筛选（§5.3）。只有当热卖 query 同时涉及类目词时，才触发类目鉴权。

#### 1.5.2 相似匹配

| 方式 | 示例 |
|---|---|
| **子串包含** | 用户"挖掘机"，Map 有"挖掘机械" → 命中 |
| **核心词匹配** | 用户"小型挖掘机"，Map 有"挖掘机械" → 命中 |

- 唯一命中 → 使用，输出时**必须说明**匹配到的类目名（§9.5）
- 多个候选 → 列出让用户选择
- 无命中 → 模糊型退化为关键词搜索；明确类目路由则告知无法识别 + 展示一级类目

#### 1.5.3 类目 Map 数据格式

Map 位于返回体 `.value` 字段中（不要把外层 `success`/`msg` 当类目数据）：

```json
{
  "success": true,
  "value": {
    "2": { "cateId": 2, "name": "食品及饮料", "parentId": null, "level": 1 },
    "201329707": { "cateId": 201329707, "name": "饮料", "parentId": 2, "level": 2 },
    "202": { "cateId": 202, "name": "软饮料", "parentId": 201329707, "level": 3 }
  }
}
```

| 字段 | 说明 |
|---|---|
| key | cateId |
| `name` | 类目名称 |
| `parentId` | 父类目 ID，一级为 null |
| `level` | 层级深度（1=一级，2=二级…） |

**路径重建（硬要求：逐级完整，禁止跳级）**：沿 `parentId` 逐级往上到 `parentId=null`，**必须包含每一级**。

> ✅ cateId=202 → 食品及饮料 > 饮料 > 软饮料
> ❌ 食品及饮料 > 软饮料（跳过"饮料"）

**展示可用一级类目**：筛选所有 `level=1` 的 entry，提取 `name` 列表展示给用户。

### 1.6 交易品 / 商机品判定

| 条件                               | `businessType`                |
| -------------------------------- | ----------------------------- |
| 明确提及商机品 / 商机定招 / 商机主题            | `CUSTOMIZATION_PRODUCT`       |
| 话术含：世界杯/世界杯营销 / 世界杯专题            | `CUSTOMIZATION_PRODUCT`       |
| 本会话连续 ≥3 次主动指定商机品（翻页不计；指定交易品则重置） | `CUSTOMIZATION_PRODUCT`（后续默认） |
| 其他（默认）                           | `HOT_PRODUCT`                 |

## 3. 固定参数集合（全字段必传）

| 字段                            | 类型       | 默认值               | 说明                                                                                         |

## 4. 场景 JSON 模板

未列出字段按 §3.2 默认值填入。

### 4.1 推荐（`scene = topicRecommendScene`）

`title=""` + `topicIds=[]`，全部字段取默认值。

**已发品**：`hasDirectProduct=true`，scene 仍为推荐（即使带关键词也覆盖为推荐）。

**⚠️ 类目筛选始终走推荐场景**：仅通过 `categoryId` 筛选（无论是否叠加关键词 `title`），`scene` 均为 `topicRecommendScene`。**不要因为有 `title` 非空就切到搜索场景**——只有纯主题名称搜索（无 categoryId）才走搜索场景。

### 4.2 搜索（`scene = topicSearchScene`）

**仅以下两种情况**使用搜索场景：

| 场景 | 关键参数 | scene |
|---|---|---|
| **主题名称搜索**（§1.3.3 + §1.3.4 退化，无 categoryId） | `title = "<名称>"`, `orderByName = "lst_tgd_prod_payed_byr_growth"` | `topicSearchScene` |
| **topicIds 精查** | `topicIds = ["12345"]`, `title = ""`, `orderByName = "lst_tgd_prod_payed_byr_growth"` | `topicSearchScene` |

**⛔ 关键词小写化（强制要求）**：在构造 `title` 字段参数时，**必须**将用户输入的关键词中所有大写英文字母转换为**小写**（例如：`"T恤"` → `"t恤"`）。由于定招后端索引对大小写敏感，此举能显著提升搜索匹配成功率。

⛔ **不要将类目筛选误判为搜索**：`categoryId + title` 的组合属于推荐场景（§4.3），不是搜索场景。

中英文关键词均可，Agent **不预处理**（不翻译、不截断、不改写）。

### 4.3 筛选（叠加在推荐或搜索之上）

scene 仍按 4.1/4.2 派生，填上筛选字段即可。

| 场景 | 关键参数 | scene |
|---|---|---|
| 类目筛选（纯 categoryId） | `categoryId = "100009092"` | `topicRecommendScene` |
| 类目 + 关键词 | `categoryId + title`（注意：仍走推荐场景） | `topicRecommendScene` |
| 多条件叠加 | `strategyTagList + recommendCountryList + categoryId + topicTagList` | `topicRecommendScene` |
| 模糊型走类目 | 匹配到 cateId → `categoryId = "xxx"` | `topicRecommendScene` |
| 模糊型退化 | 无匹配 → `title = "xxx"` + `orderByName = "lst_tgd_prod_payed_byr_growth"`（无 categoryId） | `topicSearchScene` |

## 5. tagCode 内置枚举与热卖路由

表外描述**不要发明 tagCode**（走 [E-04](error-cases.md#e-04-tab-词不在枚举)）。

### 5.1 `strategyTagList`（每次只传一个值，单选项内互斥）

| 用户表述      | 取值                        | 业务线 |
| --------- | ------------------------- | --- |
| 全网热卖      | `["GLOBAL_HOT"]`          | 交易品 |
| 站内热卖      | `["ICBU_HOT"]`            | 交易品 |
| 站内稀缺      | `["ICBU_SHORT"]`          | 交易品 |
| 海外现货/场景特供 | `["OVERSEA_TREND_TOPIC"]` | 交易品 |
| 半托管       | `["SEMI_MANAGE"]`         | 交易品 |
| (未指定)     | `[]`                      | 全部  |

> ⚠️ **引导限制**：在主动引导、推荐文案、查询引导中，**仅引导全网热卖、站内热卖、站内稀缺**三种标签。海外现货和半托管**不在引导中出现**，但如果用户**主动明确要求**查询这两个标签，仍然正常执行查询。

### 5.2 `topicTagList`（多选）

| 用户表述                   | 值                            | 业务线 |
| ---------------------- | ---------------------------- | --- |
| 近 7 日上新 / 新建主题 / 最近上新  | `"NEW_CREATE"`               | 通用  |
| 市场热卖 / 热卖（模糊）/ 卖的好     | `"HIGH_EFFECT_SHORT_SUPPLY"` | 通用  |
| 世界杯/世界杯专题              | `"WORLD_CUP"`               | 商机品 |


### 5.3 热卖路由规则（重要 ⚠️）

"热卖"是高频 query 关键词，**必须精确路由到正确的参数**。三条路径相互独立：

| 用户 Query 特征 | 路由目标 | 参数写法 | 需要类目鉴权？ |
|---|---|---|---|
| **明确 "站内热卖"**：含"站内""国际站卖的好的""站里面好的品" | strategyTagList | `strategyTagList=["ICBU_HOT"]` | ❌ 不需要 |
| **明确 "全网热卖"**：含"全网""全网卖的好""全网爆款" | strategyTagList | `strategyTagList=["GLOBAL_HOT"]` | ❌ 不需要 |
| **模糊 "热卖" 或明确 "市场热卖"**：含"热卖""市场热卖""当前热卖的""有什么卖的好的""热卖定招" | topicTagList | `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]`，**同时 `strategyTagList=[]`**（空数组，表示不限定 tab） | ❌ 不需要 |
| **热卖 + 类目词**：如"xx类目的市场热卖" | topicTagList + categoryId | `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]` + `categoryId="xxx"` | ✅ 需要 |

**核心规则**：
- **市场热卖 = `HIGH_EFFECT_SHORT_SUPPLY`**（topicTag），这是一个 1.5 级别的路由路径，非常重要
- 模糊热卖 query（无明确"站内"或"全网"修饰）**一律走 `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]`**，`strategyTagList` 设为 `[]`
- 仅当用户**额外限定**了"站内热卖"或"全网热卖"时，才对应加 `strategyTagList`
- 纯热卖路径（不涉及类目/主题搜索词）**不触发类目鉴权**，直接走推荐+筛选

**组合场景示例**：
- "市场热卖" → `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]` + `strategyTagList=[]`（纯热卖，无需类目鉴权）
- "有什么卖的好的" → `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]` + `strategyTagList=[]`（模糊热卖，无需类目鉴权）
- "全网热卖中的市场热卖" → `strategyTagList=["GLOBAL_HOT"]` + `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]`（两个参数不互斥，无需类目鉴权）
- "站内热卖近7日上新" → `strategyTagList=["ICBU_HOT"]` + `topicTagList=["NEW_CREATE"]`（无需类目鉴权）
- "家居园艺类目的市场热卖" → `topicTagList=["HIGH_EFFECT_SHORT_SUPPLY"]` + `categoryId="xxx"`（涉及类目，需要类目鉴权）

## 8. 分页与翻页上下文

- 默认 `pageSize=10`，`currentPage=1`
- 翻页**保留全部条件**，仅 `currentPage+1`
- `dataList=[]` 或 `pageSize * currentPage >= totalItem` → 到底
- 调整条件 → `currentPage` 重置为 1

**翻页上下文维护**：
- 会话内需维护当前的 `currentPage` 状态
- 用户说"还有其他主题吗""再来一页""下一页"等翻页意图时，自动将 `currentPage` 在上次值基础上 +1
- 翻页时所有其他筛选条件（strategyTagList / topicTagList / categoryId / recommendCountryList / businessType 等）**原样保留**，不可改变
- 用户主动修改了任何筛选条件 → `currentPage` 重置为 1
- 翻页到底时告知"已经到底了，没有更多结果"，不继续翻页

## 9. 输出渲染

### 9.1 差异化表格模板（根据 businessType 区分）

表格列名、列数、列顺序**根据 businessType 不同而不同**，逐字照抄，禁止改名/增列/删列，缺失数据默认 `-`，不允许缺列。

#### 9.1.1 交易品表格（`businessType = HOT_PRODUCT`）

**固定 7 列**：

```
序号 | 主题图片 | 主题名称 (ID) | 价格 | 起订量 | 主推国家 | 流量加速类型
```

#### 9.1.2 商机品表格（`businessType = CUSTOMIZATION_PRODUCT`）

**固定 7 列**：

```
序号 | 主题图片 | 主题名称 (ID) | 支持服务 | 深度定制 | 主推国家 | 流量加速类型
```

⛔ **禁止改名**：
- "价格" ≠ "价格要求" ≠ "价格区间"
- "起订量" ≠ "MOQ" ≠ "最低订购量"
- "主推国家" ≠ "目标市场" ≠ "国家/地区"
- "支持服务" ≠ "服务" ≠ "能力"
- "深度定制" ≠ "定制" ≠ "定制属性"
- "流量加速类型" ≠ "加速" ≠ "加速策略"
- ❌ 禁止新增任何未列出的列

⛔ **不允许缺列**：
- 即使某列所有行数据均为空，仍保留该列，所有单元格填 `-`
- 表格结构在所有 businessType 的查询中**保持一致（均为 7 列）**

### 9.2 序号

**序号 = `(currentPage - 1) * pageSize + 当页连续编号`**。`topicId`/`title` 缺失行删除后重新编号保持连续。翻页按追加语义，序号继续递增。

### 9.3 列字段对应

#### 9.3.1 通用列

| 表格列       | 来源字段                                                                                | 缺失处置        |
| --------- | ----------------------------------------------------------------------------------- | ----------- |
| 序号        | §9.2 公式                                                                             | 不删          |
| 主题图片      | `sampleImgUrl` ,渲染为 `![thumb](sampleImgUrl)`。若 url 以 `//` 开头，**必须强制补全 `https:`**（确保聊天窗口正常显示）；无协议前缀须补 `https://` | 写 `-`       |

**⚠️ deepCustomProperties 取值规则（重要）**：

### 9.4 表格铁律

- **列名必须与 §9.1 完全一致**（按当前 businessType 对应的模板），禁止同义词替换、禁止新增列
- **数据映射完整性（零索引对齐）**：必须从工具返回的 `datas` 数组的 **第 0 位索引** 开始映射，严禁跳过首位。
- **严禁主观过滤**：除非命中“topicId 或 title 缺失”的整行删除逻辑，否则严禁主观跳过数组中的任何条目（如跳过疑似测试数据）。
- **行数对齐**：确保渲染的行数与 `datas` 数组的实际有效长度严格对齐。在数组仍有数据未处理时，严禁出现“暂无数据”或空行占位。
- 表格前后**必须空行**；`|` 与内容间**必须空格**
- 序号列固定第 1 列，不删
- **不允许缺列**：即使整列数据为空，也保留该列并填 `-`
- `topicId` 或 `title` 缺失 → 整行删除
- **禁止省略或截断任何一行**。
- 超出 10 条的部分不渲染
- **⛔ 禁止显示主题总数（铁律，强化）**：任何情况下都不在用户可见页面展示"共查到 XX 个主题""共 XX 条结果"等总数信息。只渲染最多 10 条数据，不透露 totalItem / total 等任何总数字段。这是一条不可违反的硬规则。

A. 全部发（序号 1~5）
B. 发前 3 个（序号 1~3）
C. 自定义（请输入具体序号、topicId 或范围）
```

**askUser 规则**：
- 选项数量固定 **3 个**
- 选项内容由 AI 根据查询结果智能预测（如结果数量、主题类型、用户历史偏好等）

```

**选项预测原则**：
- 第 1 个选项通常是"全部发"
- 第 2 个选项根据查询结果特征预测（如按关键词聚类、按序号范围、按单个热门主题等）
- 第 3 个选项固定为"自定义"，允许用户自行输入

**用户响应处理**：
- 用户选择了具体选项 → 直接进入 [`topic-listing.md`](topic-listing.md) 发品流程（默认走草稿链路）
- 用户选择"自定义"并输入了具体内容 → 解析后进入发品流程
- 用户表示不需要发品 → 结束，等待下一轮交互

#### 9.6.2 原始 query 无发品意图 → 仅文字引导

用户原始 query 仅为查询意图（如"有什么定招主题""帮我查保温杯类目的定招"），查询完成并展示结果后，**不弹 askUser**，展示上述三部分引导内容（流量加速说明 + 继续查询引导 + 发品引导）即可。

用户看到引导后回复了发品指令（如"发第2个""发 88001""全部发"），**直接进入 [`topic-listing.md`](topic-listing.md) 发品流程（默认走草稿链路），不弹 askUser，不二次确认**。

#### 9.6.3 空结果不触发引导

查询返回空结果时，按 §9.5 空结果模板输出，**不弹 askUser，不展示文字引导**。

#### 9.6.4 查询引导生成质量准则 (Query-Driven Guidance)
Agent 在生成“继续查询引导”时，**其核心目标是激发并引导用户执行进一步的查询动作**。引导话术必须基于不同维度的底层逻辑进行“差异化驱动”，并确保输出质量：

**维度定义基准：**
- **全网热卖 (GLOBAL_HOT)**：站内+站外都热卖。
- **站内稀缺 (ICBU_SHORT)**：仅站外热卖。意味着供需错配，是填补空白、避开红海的信息差机会。
- **站内热卖 (ICBU_HOT)**：仅站内热卖。符合平台买家偏好，适合对标同行精准拿盘。
- **市场热卖 (HIGH_EFFECT_SHORT_SUPPLY)**：平台基于经营数据甄选的 TOP 热卖定招主题。官方背书，流量加速权重最高。

**质量对比准则：**

| 维度 | ❌ 反面案例（禁止） | ✅ 正面案例（推荐） |
| :--- | :--- | :--- |
| **业务逻辑** | **机械罗列**：单纯问用户要不要查询其他维度，不说明理由。 | **查询驱动**：基于维度定义给出运营判断，**明确呼唤查询动作**。建议结构：“现状判断 + **强烈推荐查询** + 利益点(Why)”。 |
| **话术文案** | “这里还可以查询全网热卖和站内稀缺的主题，你需要再查查其他的吗？” | “针对你关注的[品类]，我建议你立即**查询站内稀缺**主题。这类商品目前在站外已成爆款但站内供给不足，是**避开红海、利用信息差**拿盘的最佳时机，要不要现在查查看？” |
| **价值传递** | **模糊不清**：不告诉用户查询之后有什么好处。 | **利益对齐**：明确关联到“转化率”、“竞争程度”或“流量权重”，**以此吸引用户点击或回复以执行查询**。 |
| **话术文案** | “你可以试试查询市场热卖主题，点击链接可以查看加速权益。” | “想追求更高的发品转化吗？我推荐你**查询市场热卖**主题，这些是平台基于大数据甄选的 TOP 级商机，匹配后能获得**极高的流量加速权重**。需要帮你展示吗？” |

**⛔ 禁用词限制（合规红线）：**
- 引导语中**严禁使用绝对化/最最高级词汇**，包括但不限于：“最”、“第一”、“首个”、“冠军”、“顶级”、“极品”等。
- 引导语应采用客观、委婉的表达，如使用“高”、“较高”、“重点”、“核心”等替代。
- 示例：将“流量最高”改为“流量高”或“流量表现突出”。

### 9.7 引导触发（跨 Skill 场景）

完成"市场调研 / 行业趋势 / 竞对分析"等回答后，可追问商家是否要看相关定招主题：

> 「你关注的 **{品类}**，平台目前有相关的定招主题，满足要求有机会获得更多曝光，需要我帮你查一下吗？」

用户确认 → 进入查询流程。拒绝或忽略 → 不再追问。
