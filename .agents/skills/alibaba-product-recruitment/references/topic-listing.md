## 1. 工具

| 工具名                              | 用途                         | 调用形态                                          |
| -------------------------------- | -------------------------- | --------------------------------------------- |
| `listing_product_draft_by_topic` | 根据定招主题发布草稿品（将品存入草稿箱，非直接发品） | `{ topicId }`，topicId 为 number 类型             |
| `publish_product_draft_online`   | 将商家草稿箱中的品正式发布             | `{ categoryId, draftProductId }`，均为 number 类型 |

**默认发品链路**：`listing_product_draft_by_topic` → 展示草稿结果 → **用户手动确认** → `publish_product_draft_online` → 展示发布结果。

## 2. 发品意图识别

### 2.1 识别标志

- 含"发品/发布/上架/listing"等动词 + topicId 或对本会话结果的指代
- 含定招/征品上下文 + 发品动作词（如"帮我在行业定向征品下发一款""可以批量上发饰类目热卖定向征品吗"）
- 如"帮我发 topicId=88001""把第2个主题发了""发这几个主题品""帮我一键发布行业定向征品中的商机品定招"

### 2.2 发品工作流判定（核心逻辑）

用户说"发品"时，Agent 需要根据会话上下文自动判断执行路径：

| 会话状态 | 执行路径 | 说明 |
|---|---|---|
| **原始 query 有发品意图** | 查询 → **存草稿** → **询问确认** → 正式发布 | 用户意图明确，分段执行 |
| **原始 query 无发品意图 + 直接说发品** | **存草稿** → **询问确认** → 正式发布 | 存完即止，等待用户下一步 |
| **同会话中该主题已有草稿** | **直接正式发布**（需确认） | 草稿已存在，用户说"发品"即发线上 |
| **多轮对话后提到存过草稿的主题** | **askUser 确认**：正式发布 or 重新存草稿 | 跨轮需确认意图 |

**⛔ 铁律**：
- **严禁全流程自动执行**：存草稿成功后**必须停止**并展示结果，严禁静默调用 `publish_product_draft_online`。
- **强制分段确认**：存草稿完成后，必须先询问：“草稿已保存，是否立即发布到线上？” 只有在用户明确回复“发布”“确认”“是的”等肯定意图后，方可执行正式发布步骤。
- **风控展示优先级**：存草稿成功后的询问中，必须包含风控免责文案（§7.4）。

### 2.3 内部路由

本 Skill 统一接收所有定招意图后，在内部做如下判定：

| 会话状态 | 路由 |
|---|---|
| 本会话已有查询结果 + 用户指定了 topicId/序号 | **按 §2.2 判定执行路径**（检查是否有草稿记忆） |
| 本会话已有查询结果 + topicId 不在结果中 | 先查验该 topicId（E-16），有结果后按 §2.2 走发品 |
| 本会话无查询结果 + 用户给了 topicId | **先用 topicIds 查出该主题信息展示**，再按 §2.2 走发品 |
| 本会话无查询结果 + 无 topicId | 告知需先查询，引导用户提供类目/关键词进入查询 |

**当前阶段约束**：发品必须在本会话执行过定招主题查询后才可执行（先查后发）。

## 3. 前置条件

| 条件 | 说明 |
|---|---|
| 本会话已有查询结果 | 必须已成功调用 `farseer_topic_search` 且 `dataList` 非空 |
| 用户指定了目标 | 通过 topicId、序号或范围指定了发品目标 |
| topicId 有效 | 必须为纯数字，且存在于本会话查询结果中 |

**不满足前置条件时的处置**：
- 本会话无查询结果 + 用户给了 topicId → **先用 `topicIds` 调 `farseer_topic_search` 查出该主题信息展示**，查验通过后**按 §2.2 走发品流程**
- 本会话无查询结果 + 无 topicId → 告知"发品前需要先查询定招主题"，引导用户提供类目/关键词进入查询

## 4. 发品触发

发品可通过以下方式触发：

**方式一：通过 askUser 弹窗**（原始 query 有发品意图时）
- 用户选择了 askUser 的具体选项 → 直接进入发品流程（按 §2.2 判定）
- 弹窗中的风控免责小字已在查询阶段展示（见 [`topic-query.md`](topic-query.md) §9.6.1）

**方式二：用户直接输入发品指令**（原始 query 无发品意图时，看到文字引导后回复）
- 用户直接输入序号（如"发第2个"）→ 按 §2.2 判定执行路径
- 用户直接输入 topicId（如"发 88001"）→ 按 §2.2 判定执行路径
- 用户直接输入范围（如"发第1~3个""全部发"）→ 按范围逐个处理
- 用户输入模糊无法解析 → 反问明确目标

**方式三：多轮对话中提到之前存过草稿的主题**
- 跨轮且有草稿记忆 → **弹 askUser 确认**意图（正式发布 / 重新存草稿）

**前置校验（铁律）**：无论用户通过何种方式指定 topicId，发品前**必须校验**该 topicId 是否在本会话查询结果中。不在结果中时，按 E-16 处置（先查验再发品）。

## 5. 序号解析规则

用户通过序号指定发品目标时，按以下规则解析：

| 用户表述 | 含义 | 示例 |
|---|---|---|
| **"发第N个"** | 当前页的第 N 个 | 第 2 页时"发第2个" → 当前页第 2 条（全局序号 12） |
| **"发序号N"/"序号N"** | 全局序号 | "发序号2" → 全局序号 2（第 1 页第 2 条） |
| **逗号分隔序号** | 全局序号 | "序号 2, 5, 6" → 全局序号 2、5、6 |
| **范围** | 全局序号范围 | "发序号1~5" → 全局序号 1 到 5 |

**核心区分**："第N个"是相对当前页的定位，"序号N"是全局绝对定位。

**翻页后的全局序号有效性**：翻页后，之前页的查询结果在会话内**仍然有效**。用户可以通过全局序号（如"发序号 3"）发品任何已查出的主题，不限于当前页。会话内所有页的查询结果构成一个**累积结果集**，全局序号在整个会话内唯一且持续有效。

## 6. 发品工作流（默认草稿链路）

默认发品流程为**两阶段**（中间需用户确认）：先发草稿 → 用户确认 → 再正式发布。

```
┌─────────────────────────────────────────────────────────────────────────┐
│  阶段一：发草稿                                                          │
│  ┌───────────────────────────────────────────────────────────────┐      │
│  │ 第 1 批（最多 5 个 topicId）→ 并行调用 listing_product_draft  │      │
│  │       → 全部返回后 → 立即渲染该批草稿结果表格                    │      │
│  └───────────────────────────────────────────────────────────────┘      │
│                              ↓                                          │
│  ... 逐批执行，每批都是"并行调用→立即渲染"完整闭环 ...                     │
│                              ↓                                          │
│  全部草稿完成 → ⛔ 停止执行，等待用户“发布/确认”指令                       │
└─────────────────────────────────────────────────────────────────────────┘
                                ↓
                        【 用户确认发布 】
                                ↓
┌─────────────────────────────────────────────────────────────────────────┐
│  阶段二：正式发布                                                         │
│  ┌───────────────────────────────────────────────────────────────┐      │
│  │ 第 1 批（最多 5 个 draftProductId）→ 并行调用 publish          │      │
│  │       → 全部返回后 → 立即渲染该批发布结果表格                    │      │
│  └───────────────────────────────────────────────────────────────┘      │
│                              ↓                                          │
│  ... 逐批执行 ...                                                       │
│                              ↓                                          │
│  全部发布完成 → 展示 §9.4 常态化引导文案                                  │
└─────────────────────────────────────────────────────────────────────────┘
```


⛔ **禁止**：一次性并行超过 5 个调用（无论是草稿还是发布）。超过 5 个时必须分批，每批最多 5 个。
⛔ **禁止**：把所有批次的结果攒到最后统一渲染。
⛔ **禁止**：跳过草稿阶段直接调用 publish_product_draft_online。

**自检**：如果你的输出中只出现了一次包含所有品的结果表格，说明你违反了此规则。正确的输出应该是多次独立的结果表格，每次最多 5 行，且草稿和发布分开展示。

## 7. 步骤一：发草稿 `listing_product_draft_by_topic`

### 7.1 入参

```json
{ "topicId": 88001 }
```

- `topicId` 为 number 类型（不是字符串）
- **批量场景下最大允许 5 个并行发草稿**

### 7.2 返回结构

成功：
```json
{
  "success": true,
  "draftProductId": 1601817693176,
  "categoryId": 100009092,
  "productTitle": "Baby Diaper Bag",
  "errorMessage": null
}
```

失败：
```json
{
  "success": false,
  "draftProductId": null,
  "categoryId": null,
  "productTitle": null,
  "errorMessage": "提交草稿请求失败",
  "errorCode": "DRAFT_SUBMIT_ERROR"
}
```

### 7.3 关键字段说明

| 字段 | 说明 |
|---|---|
| `draftProductId` | 草稿商品 ID，发草稿成功时返回，供后续 `publish_product_draft_online` 使用 |
| `categoryId` | 类目 ID，发草稿成功时返回，供后续 `publish_product_draft_online` 使用 |
| `productTitle` | 商品标题，可能为空 |
| `errorMessage` | 失败原因 |

**⛔ 草稿成功但后续发布失败的 topicId，仍然需要在草稿结果表格中展示为"存草稿成功"，不可因后续发布失败而改变草稿状态。**

### 7.4 草稿结果渲染

草稿阶段每批完成后**立即渲染**该批草稿结果表格（§9.1），然后继续下一批草稿或进入发布阶段。

**⛔ 合规风控文案（铁律）**：草稿全部完成后，**若存在至少一个存草稿成功的商品**，在引导用户正式发布**之前**，必须展示以下风控小字：

> 💡 **合规提示**：存草稿直接使用系统推荐图片，直接发布前请确保信息真实合规并获得授权，违规可能影响权益或被处罚，平台不对商家的使用行为提供任何保证或承担任何责任。

此文案**不可省略**，每次有草稿成功时都必须展示。如果全部失败，则不展示。

## 8. 步骤二：正式发布 `publish_product_draft_online`

### 8.1 前置条件

**仅对发草稿成功的品执行发布**。草稿失败的品不进入发布阶段。

### 8.2 入参

```json
{ "categoryId": 100009092, "draftProductId": 1601817693176 }
```

- `categoryId` 和 `draftProductId` 均为 number 类型
- 这两个值从 `listing_product_draft_by_topic` 成功返回中获取（§7.3）
- **批量场景下最大允许 5 个并行发布**

### 8.3 返回结构

成功：
```json
{
  "success": true,
  "productId": 1601817693176,
  "errorMessage": null
}
```

失败：
```json
{
  "success": false,
  "productId": null,
  "errorMessage": "商品发布失败：标题含有禁限售词汇",
  "errorCode": "PUBLISH_ERROR"
}
```

### 8.4 发布结果渲染

发布阶段每批完成后**立即渲染**该批发布结果表格（§9.2），然后继续下一批发布。全部完成后展示常态化引导文案（§9.4）。

## 9. 结果渲染

### 9.1 草稿结果表格

**固定 5 列**：

```
序号 | 商品标题(商品ID) | 主题名称(主题ID) | 发布状态 | 操作
```

| 发布状态 | 操作列内容 |
|---|---|
| 📝 **存草稿成功** | [编辑草稿]({editLink})（§9.5） |
| ❌ **存草稿失败** | [主题链接]({topicLink})，建议手动发布 |

**超链接规则**：
- ✅ **存草稿成功**行：编辑链接**仅出现在「操作」列**
- ✅ **存草稿失败**行：纯文本展示失败原因，无链接
- ⛔ **禁止**在「商品标题(商品ID)」「主题名称(主题ID)」「发布状态」列添加超链接

**列数据来源**：

| 列 | 数据来源 | 格式 |
|---|---|---|
| 序号 | 发品顺序编号 | 数字 |
| 商品标题(商品ID) | API 返回的 productTitle + draftProductId | `标题` + `<br>ID：` + `draftProductId` |
| 主题名称(主题ID) | 查询结果中的主题名称 + topicId | `主题名称` + `<br>ID：` + `topicId` |
| 发布状态 | API 返回的 success | 图标+文字 |
| 操作 | 根据状态生成 | 编辑链接或失败原因 |

**商品标题截断处理（排版优化）**：
- **强制截断长度 ($N=60$)**：为了表格排版美观，若 API 返回的 `productTitle` 超过 **60** 个字符，必须截取前 60 个字符并追加 `...`；若不超过 60 个字符则完整展示。
- **背景说明**：国际站标题通常较长，截断至 60 字符（约 10-12 个英文单词）可确保核心词可见，同时将表格单行高度控制在 3 行左右。

- draftProductId 缺失 → 商品标题列仅显示标题文本，不显示 ID 行

**渲染示例（草稿）**：

```markdown
| 序号 | 商品标题(商品ID) | 主题名称(主题ID) | 发布状态 | 操作 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | Baby Diaper Bag<br>ID：1601737818311 | Diaper Bag - Blue<br>ID：88001 | 📝 **存草稿成功** | [编辑草稿](https://post.alibaba.com/product/publish.htm?pubAction=draft&itemId=1601737818311&industryCollectTopicId=88001&fromSite=aw-collect-topic) |
| 2 | Travel Mummy Pack<br>ID：1601737818310 | Mummy Bag - Pink<br>ID：88002 | 📝 **存草稿成功** | [编辑草稿](https://post.alibaba.com/product/publish.htm?pubAction=draft&itemId=1601737818310&industryCollectTopicId=88002&fromSite=aw-collect-topic) |
| 3 | Cosmetic Bag<br>ID：1601737818309 | Cosmetic Organizer<br>ID：88003 | ❌ **存草稿失败** | [主题链接](https://hz-productposting.alibaba.com/product/collect_product.htm?subMenuCode=product_direct_collect_manage&strategy_topicId=88003&strategy_tagKey=ICBU_HOT)，建议手动发布 |
```

### 9.2 发布结果表格

**固定 5 列**（列名与草稿一致）：

```
序号 | 商品标题(商品ID) | 主题名称(主题ID) | 发布状态 | 操作
```

| 发布状态 | 操作列内容 |
|---|---|
| ✅ **已发布** | 已自动上架 |
| ❌ **发布失败** | [编辑草稿]({editLink})，建议手动上架 |

**超链接规则（重要）**：
- ✅ **已发布**行：所有列均为**纯文本**，不添加任何超链接
- ✅ **发布失败**行：操作列展示编辑链接（格式见 §9.5），不透传具体失败原因
- ⛔ **禁止**在「商品标题(商品ID)」「主题名称(主题ID)」「发布状态」列添加超链接

**列数据来源**：

| 列 | 数据来源 | 格式 |
|---|---|---|
| 序号 | 发品顺序编号 | 数字 |
| 商品标题(商品ID) | 草稿返回的 productTitle + productId（或 draftProductId） | `标题` + `<br>ID：` + `productId` |
| 主题名称(主题ID) | 查询结果中的主题名称 + topicId | `主题名称` + `<br>ID：` + `topicId` |
| 发布状态 | API 返回的 success | 图标+文字 |
| 操作 | 根据状态生成 | "已自动上架"或编辑链接（仅限发布失败） |

**商品标题截断处理（排版优化）**：
- **强制截断长度 ($N=60$)**：为了表格排版美观，若 API 返回的 `productTitle` 超过 **60** 个字符，必须截取前 60 个字符并追加 `...`；若不超过 60 个字符则完整展示。
- **背景说明**：国际站标题通常较长，截断至 60 字符（约 10-12 个英文单词）可确保核心词可见，同时将表格单行高度控制在 3 行左右。

### 9.4 常态化引导文案


发布全部完成后，根据最终发布状态选择对应文案，追加在结果表格下方：

**⛔ 合规风控文案（铁律）**：发布结果展示**之后**，**若存在至少一个自动发布成功或保存草稿成功的商品**，必须追加以下风控小字：

> 💡 **合规提示**：发品直接使用系统推荐图片，请确保信息真实合规并获得授权，违规可能影响权益或被处罚，平台不对商家的使用行为提供任何保证或承担任何责任。

此文案**不可省略**，只要有成功项（草稿或发布）就必须展示。如果列表全部发布失败且无成功草稿，则不展示。

**存在自动发布成功的商品时**：

### 9.5 草稿编辑链接格式

草稿成功行的「操作」列必须拼接以下编辑链接：

```
https://post.alibaba.com/product/publish.htm?pubAction=draft&itemId={draftProductId}&industryCollectTopicId={topicId}&fromSite=aw-collect-topic
```

### 9.6 主题详情链接格式

存草稿失败行的「操作」列必须拼接以下链接用于手动发布：

```
https://hz-productposting.alibaba.com/product/collect_product.htm?subMenuCode=product_direct_collect_manage&strategy_topicId={topicId}&strategy_tagKey={tagCode}
```

**参数说明**：

| 参数 | 来源 | 说明 |
|---|---|---|
| `draftProductId` | `listing_product_draft_by_topic` 返回的 `draftProductId` 字段 | 草稿商品 ID |
| `topicId` | 当前操作的定招主题 ID | 从查询结果中获取 |
| `tagCode` | 当前主题的策略标签 | 从查询结果获取，缺失或不匹配有效 Tab 代码时强制默认为 `ICBU_HOT`（见 SKILL.patch.md 限制） |
| `fromSite` | 固定值 `aw-collect-topic` | 来源标识 |

**⛔ 铁律**：
- 三个参数**缺一不可**，否则链接无效
- `draftProductId` 和 `topicId` 均为**数字**，不加引号
- 每个草稿成功的品都必须有**独立的编辑链接**，不可丢失

## 10. 发品铁律

| 规则                     | 说明                                                    |
| ---------------------- | ----------------------------------------------------- |
| **先查后发**               | 无本会话查询结果时不可直接发品，需先查出主题信息                              |
| **不可盲发**               | topicId 必须来自查询结果，不可凭空使用用户随口说的 ID（先查验）                 |
| **productId 必须展示**     | 发品成功后必须将 productId 展示在「商品标题(商品ID)」列中，格式为 `标题` + `<br>ID：` + `productId` |
| **标题截断展示** | 发品结果表格（草稿/发布）中的商品标题若超过 **60** 字符，必须截取前 60 位并追加 `...` |
| **发布成功无超链接** | 发布结果表格中所有行均为纯文本，不添加任何超链接；草稿结果表格仅操作列可有编辑链接 |
| **批量最大 5 并发逐批执行** | 每批最多 5 个并行调用（草稿或发布均适用），一批完成后**立即渲染该批结果表格**，再处理下一批，禁止超过 5 个并发，禁止攒到最后统一渲染 |
| **草稿和发布分开展示** | 草稿结果和发布结果是两个独立的表格，不可合并，各自分批渲染 |
| **所有品必须渲染**           | 用户发多少个品，不管成功还是失败，所有品都必须出现在结果表格中，绝不允许丢失数据            |
| **缺失退化显示**             | 任何字段数据缺失时显示 `-`，不可因缺失而删行或删列                          |
| **失败品允许重试**             | 用户可通过序号对失败的品单独重试发品，无需重新查询（详见下方重试流程说明）                             |
| **草稿链接不可丢失**         | 草稿结果中每个成功商品都必须有独立编辑链接                                 |
| **草稿失败不进发布** | 草稿失败的品不进入发布阶段，仅在草稿结果表格中标记失败                             |

**失败重试流程说明**：

用户对失败的品说"重试序号N"时，根据失败阶段决定重试范围：

| 失败阶段 | 重试操作 | 说明 |
|---|---|---|
| **草稿失败** | 重新执行草稿 → 成功后执行发布 | 草稿未成功，无 draftProductId，必须重走完整流程 |
| **发布失败（草稿已成功）** | **仅重试发布**，使用草稿成功时保存的 `categoryId` + `draftProductId` | 草稿已存在，无需重新创建，直接调 `publish_product_draft_online` |

- 重试发布时不需要重新调用 `listing_product_draft_by_topic`
- 重试后按正常流程渲染对应阶段的结果表格

## 11. 兜底处理

| 场景 | 处置策略 |
|---|---|
| 网络/MCP 调用错误 | 自动重试一次。若仍失败，向用户报告错误并终止流程 |
| 查询无结果 | 明确告知当前筛选范围无匹配定招主题，引导用户降低要求重新查询 |
| 无指定类目查询权限 | 明确告知当前类目不在用户经营范围内；告知用户可查询的类目范围、引导换类目 |
| 发草稿超时 | 明确告知用户超时情况，并提供手动跟进指引 |
| 发布超时 | 明确告知用户超时情况，草稿已保存，用户可前往卖家后台手动发布 |
| 草稿全部失败 | 不进入发布阶段，展示草稿失败结果表格 + "全部失败"引导文案 |
| 部分草稿成功 | 仅对成功的品进入发布阶段，草稿失败品保留在草稿结果表格中 |
